## Deployed-host evidence and limits

Read-only deployed `/app/BTCPayServer.deps.json` identifies 2.4.7. `/app/BTCPayServer.dll` SHA-256 `edcd6bc856988846559d6736d9a3955cd14671cc55cffb7ab257e907308572c9` was independently verified after a read-only copy. PE metadata, without assembly loading/execution, confirms ListApps' exact `/stores/{storeId}/apps` GET, policy `btcpay.store.canmodifystoresettings`, and scheme `Identity.Application`; Greenfield GetAllApps instead specifies `Greenfield.APIKeys,Greenfield.Basic`. Anonymous GETs to the authorized store's UI route returned 302 to `/login` with redirect following disabled; the Greenfield store route returned 401. No cookie/API key was synthesized or collected to pretend an authenticated live acceptance occurred.

A narrowly selected non-secret DB read found an active PointOfSale with DefaultView=2 (Light/Keypad) and EnableShoppingCart=false. No settings object, customer record, cookie or credential was printed. Detailed primary-source snapshots and safe host/route receipts are retained in the private durable worklog. The actual tablet CookieManager session and rendered authenticated response still require device acceptance; source/PE evidence is not that acceptance.

## Client boundary

`PosDiscoveryClient` performs exactly one GET to the locally constructed exact-origin/exact-store UI route, with the existing CookieManager session held only in memory. Redirects are disabled; HTTP status is preserved to distinguish login/redirect, permission, missing route and other failure. No API-key provisioning, passwords, anonymous enumeration, JSON API assumptions, JavaScript bridge, POST or invoice creation.

`PosDiscovery` is a narrow, fail-closed adapter for that known HTML view, not a general HTML scraper. It requires the complete single table/thead/tbody envelope and consumes every body row/cell with no unexplained remainder before counting candidates; truncated second rows or incomplete containers cannot turn a multiple-app response into an automatic single-app launch. It excludes scripts/styles/templates/comments, requires three-column app rows, unique bounded app IDs, exact canonical configure paths and exact owner-store settings links. Only a structurally complete `Point of Sale - Keypad` classification qualifies. The other three proven POS enum styles are explicitly excluded; missing/unknown/partially rendered POS classifications reject the entire response instead of reducing cardinality. The built-in Crowdfund route/type is recognized as non-POS (`Plugins/Crowdfund/CrowdfundPlugin.cs` and `Controllers/UICrowdfundController.cs` at the same pinned ref); unrecognized plugin routes/types fail closed rather than being silently skipped. Unknown app-row markup, duplicate attributes/IDs, foreign links, oversize responses or >100 rows reject the whole result rather than silently choosing a surviving first app. Translated/changed styles cannot become a guessed keypad. Unsupported layouts get retry/settings/manual-fallback guidance. HTML names are display-only, entity-decoded, control-stripped and code-point bounded.

Discovery runs off the UI thread; pause/destruction cancels network work and invalidates generation tokens. Results and every selection require the current resumed generation plus exact origin/store. Selecting one app invalidates the attempt. Nothing is persisted as a discovered default, so each entry rechecks current active apps and multiple keypads always require explicit choice. A manually saved legacy URL is offered only as an explicit profile-bound fallback. The established WebView trust restrictions and old PaymentOperationStore admission/recovery remain unchanged.

Bounds: 512 KiB body, 100 app rows, 10-second connect/read timeouts, 15-second body deadline and a 25-second whole-request disconnect watchdog, no redirects or retries inside a request. Operator Retry is explicit. No server/plugin changes are required. Android native POS NFC payment support, invoice cancellation, hardware acceptance and payment settlement are not claimed.
